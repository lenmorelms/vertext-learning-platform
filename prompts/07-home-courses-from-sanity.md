# 07 — Home page courses from Sanity

## Goal

Replace the hardcoded three course constant in `app/page.tsx` with courses read from the seeded Sanity dataset through the existing server only data layer. Nothing else on the home page changes.

## Skills and docs read

- `AGENTS.md` (sections 3, 5, 7, 12, 13).
- sanity-best-practices (GROQ with `defineQuery`, TypeGen for query result types, slicing in GROQ, not in JS).
- `prompts/02-home-page.md` (decision 3 promised this swap), `prompts/06-course-page.md` (format helpers and cover rendering).

## Code inspected

- `app/page.tsx`: `courses` constant with local SVG icons and preformatted duration strings.
- `sanity/queries.ts` `COURSES_QUERY`: all courses ordered by title, with `coverImage`, `level`, `moduleCount`, `durationSeconds`. `sanity/data.ts` `getCourses()`.
- `components/ui/cards.tsx` `CourseCard layout="stacked"`: takes an `icon` node (88px slot), title, summary, level, duration string, module count.
- `studio/sanity.cli.ts`: TypeGen scans `../sanity/**` and writes `../sanity.types.ts` (`npm run typegen` in `studio/`).
- `lib/format.ts`: `formatDuration`, `capitalize`.
- Seed: 10 courses, 4 popular. Covers are photos. Nothing else references `public/course-icons/`.

## Decisions and assumptions

1. **Which courses.** The reference shows one row of three with "View all courses", so the home page shows **3 featured courses**: popular first, then by student count, then title. With the seed that is Python for Data Work, Building AI Apps with LLMs, TypeScript for Application Developers.
2. **New query** `FEATURED_COURSES_QUERY` in `sanity/queries.ts`, ordered and sliced in GROQ (`[0...3]`), projecting only the card fields. New helper `getFeaturedCourses()` in `sanity/data.ts`. TypeGen is regenerated so the result is typed.
3. **Icon** is the course `coverImage` (the schema says it doubles as the small course icon), cropped square to 88px via `urlFor` + `next/image`, rounded like the reference tiles. No cover → an empty neutral tile.
4. **Formatting** uses `formatDuration` and `capitalize`, so seeded values render as `1h 59m` and `Intermediate`.
5. **Remove `public/course-icons/`** (three SVGs), now unused.
6. If the dataset returns no courses, the section shows the heading and link with no cards (no invented content).

## Requirements

- Home page is still a server component; the fetch goes through `sanityFetch` (`server-only`, cached, tagged `course`).
- Card links go to `/courses/<slug>`, which now resolves to the course page.
- Layout, spacing, and type are unchanged from the current page.

## Security considerations

- Reads stay server side with the server only read token. The browser receives rendered HTML and `cdn.sanity.io` image URLs only.
- No params from the request reach the query.

## Acceptance criteria

- `/` shows three seeded courses with their cover, title, summary, level, duration, and module count from Sanity.
- Clicking a card opens its course page.
- No reference to `/course-icons/` remains.
- Type check, lint, and build pass.

## Checks to run

1. `cd studio && npm run typegen`
2. `npx tsc --noEmit`
3. `npm run lint`
4. `npm run build`
5. Load `/` on the dev server

## Manual test steps

1. Open `http://localhost:3000/`.
2. The All Courses row shows Python for Data Work, Building AI Apps with LLMs, and TypeScript for Application Developers with seeded covers and meta.
3. In the Studio, change a popular flag or summary and publish. Within a few minutes (cache life) the home row reflects it.
4. Click a card and confirm the course page opens.
